## Is there a specific, real research concept or project called "harness" or "harness2" style self-improvement?

### Takeaway

All of them define a "harness" the same way: the prompts, tools, memory, guardrails, and orchestration code wrapped around a frozen model, as distinct from the model's weights.

### Cited Findings
- **Harness² (Harness^2): "Recursive Agent Harnessing for an Open World"** — arXiv:2610.14224 (submitted Oct 9, 2026, cs.AI). Authors listed on the arXiv page: Ruiyao Xu, Yanfei Chen, Zhongying CuiZhu, Bhavana Dalvi Mishra, Yifei Ming, Han Yu, Rujun Han, Chen-Yu Lee, Tomas Pfister. Proposes a "plug-and-play, recursive agent harnessing framework" with two levels: **task-level recursion** (a contrastive "Propose-Probe-Compose" loop that edits the harness for the current task with no ground-truth verifier) and **harnessing-level recursion** (extracts reusable experience/lessons from those edits into a persistent library for future tasks). — [arXiv:2610.14224](https://arxiv.org/abs/2610.14224)

An LLM agent improves its *own* harness (no human engineer, no stronger external agent) via a loop of: (1) weakness mining from execution traces, (2) harness proposal of minimal/diverse edits, (3) proposal validation through regression testing. On Terminal-Bench-2.0, held-out pass rates rose from 40.5%→61.9% (MiniMax M2.5), 23.8%→38.1% (Qwen3.5-35B-A3B), and 42.9%→57.1% (GLM-5). ## What are the best self-correcting and self-documenting agent system designs (reflection, self-critique, automatic postmortem generation)?

### Takeaway
The canonical self-correction lineage runs from **Reflexion → Self-Refine → CRITIC** (verbal self-critique, then critic-revise loops, then tool-grounded critique), and the 2026 "harness self-improvement" wave above is best understood as the evolution of this lineage applied to the scaffold itself rather than a single task attempt. For self-documenting/postmortem-style designs, the clearest production-grade example found is Anthropic's "Dreaming" feature for Managed Agents, plus the open research pattern of persistent experience/behavioral-rule libraries (Voyager, ExpeL, and the "Accumulated Behavioral Rules" paper).

### Cited Findings
- **Reflexion** (arXiv:2303.11366) is the widely-cited canonical verbal self-critique loop: after a failed attempt, the agent writes a natural-language reflection on what went wrong and carries that reflection into its next attempt, with no model weight updates — described in a 2026 LLM-agent survey as a form of "verbal reinforcement." — [survey: arXiv:2601.12560](https://arxiv.org/pdf/2601.12560)
- **Self-Refine** is characterized (via the same 2026 survey) as an iterative generate→critique→revise loop using the model's own judgment as the critic.
- **CRITIC** extends this by validating revisions against external tools (e.g., code interpreters, search) rather than relying solely on the model's self-judgment — per the same survey. — [arXiv:2601.12560](https://arxiv.org/pdf/2601.12560)
- **Voyager** (arXiv:2305.16291, Minecraft embodied agent): keeps a frozen GPT-4 agent but builds a persistent, growing **skill library** — each verified skill (working code) is embedded and stored in a vector database, keyed by a natural-language description generated by GPT-3.5; new tasks retrieve the top-5 relevant skills. Commentary describes the result as "an agent that got measurably better over time without any change to the underlying model." — [arXiv:2305.16291](https://arxiv.org/pdf/2305.16291)
- **ExpeL** distills recurring patterns across past trajectories into reusable natural-language insights, rather than a code/skill library — agents autonomously gather experience and extract insight text, applied to future tasks. (Characterization drawn from a secondary survey summary; the primary ExpeL paper itself was not directly fetched in this pass.)
- **Darwin Gödel Machine (DGM)** (arXiv:2505.22954, Sakana AI + collaborators): a coding agent that rewrites its *own agent code* (not weights) and empirically validates each self-modification against benchmarks, keeping an open-ended **archive** of agent variants (so a low-scoring ancestor can still seed a later breakthrough — avoids greedy-hillclimbing dead ends). Reported results: SWE-bench 20.0%→50.0%, Polyglot 14.2%→30.7%. Explicitly framed as a practical, empirical substitute for the theoretical (and practically unprovable) Gödel machine. Public code at [github.com/jennyzzt/dgm](https://github.com/jennyzzt/dgm) (~2.2k stars, 339 forks per OSS Insight, though exact current star count wasn't independently re-verified live). — [arXiv:2505.22954](https://arxiv.org/pdf/2505.22954), [Sakana AI project page](https://sakana.ai/dgm/)
- **ADAS / Meta Agent Search** (arXiv:2408.08435, "Automated Design of Agentic Systems," Shengran Hu, Cong Lu, Jeff Clune; ICLR 2025): a meta-agent writes entirely new agent *designs as code* and adds each to a growing archive that informs future designs — covers prompts, tool use, and workflow structure, not just incremental edits. Discovered agents reportedly outperformed hand-designed state-of-the-art agents on coding, science, and math tasks, and the advantage transferred across domains and models. — [arXiv:2408.08435](https://arxiv.org/pdf/2408.08435)
- **"Self-Improving AI Coding Agents Through Accumulated Behavioral Rules"** (arXiv:2607.13091, Aditya Aggarwal & Nahid Farhady Ghalaty; accepted at IEEE ICE/ITMC 2026): a *production* (not benchmark-only) closed-loop system where every accepted human code-review comment becomes a persistent, version-controlled "behavioral rule." Deployed across a 35+ microservice platform, the rule set grew from 5→18 rules plus 15+ language-specific standards and a 15-item self-review checklist, all mined from real review feedback. Measured 0% recurrence rate for error classes with an associated rule, across 11 recorded working sessions (code generation, PR review, incident investigation, cross-service refactoring). Authors explicitly frame this as improvement "without changing a single model weight." No GitHub repo was found linked from the paper. — [arXiv:2607.13091](https://arxiv.org/abs/2607.13091)
- **Anthropic "Dreaming"** (announced May 6, 2026, part of a four-part Claude Managed Agents update alongside outcomes-based grading, multi-agent orchestration up to 20 parallel subagents, and webhooks): a scheduled *background* process that reviews an agent's past sessions, flags recurring errors, and extracts successful patterns into structured "playbooks" — explicitly distinguished from ordinary conversational memory. Vendor-reported customer results: Harvey saw a 6x completion-rate lift; Wisedocs cut review time 50%. These are vendor/customer-reported figures, not independently audited. — [beri.net](https://www.beri.net/article/2026-05-10-anthropic-dreaming-claude-agents-harvey-6x-self-improving), [techstrong.ai](https://techstrong.ai/agentic-ai/dream-on-anthropics-new-agentic-capability-lets-ai-self-correct/)
- A critique of "Dreaming"-style memory-based self-improvement (Mitch Ashley, Futurum Group, via techstrong.ai): memory that changes between runs needs lineage tracking, poisoning detection, and drift telemetry that current tooling doesn't expose. A related independent analysis proposes a "Wipe Test" — checking whether an agent's performance gains survive when its external memory is deleted — arguing many "self-evolving" agent claims are actually gains from accumulated memory, not genuine model/skill improvement. — [techstrong.ai](https://techstrong.ai/agentic-ai/dream-on-anthropics-new-agentic-capability-lets-ai-self-correct/), [Micheal's Substack](https://micheallanham.substack.com/p/self-evolving-agents-real-learning)
- A 2026 survey, **"Adaptation of Agentic AI: A Survey of Post-Training, Memory, and Skills"** (arXiv:2512.16301, Pengcheng Jiang + 33 co-authors including Jiawei Han, Yejin Choi), gives a four-paradigm taxonomy: **A1** (model adaptation from tool-execution feedback — SFT/preference-opt/RL), **A2** (model adaptation from agent-output signals), **T1** (agent-agnostic reusable tool modules), **T2** (agent-supervised tool/memory/skill-library construction). Memory and skill libraries (Voyager-style, behavioral-rules-style) fall under **T2**, cleanly separating "no-retraining, scaffold/memory-only" improvement from the A1/A2 weight-update paradigms the user's project is explicitly excluding. — [arXiv:2512.16301](https://arxiv.org/abs/2512.16301)

### Inferences
- There is a clear, three-tier escalation visible across these systems, each more advanced than a simple propose→evaluate→archive baseline: (1) **single-trajectory self-critique** (Reflexion/Self-Refine/CRITIC — fixes one task attempt), (2) **persistent experience/skill accumulation** (Voyager, ExpeL, Accumulated Behavioral Rules — fixes recurring error classes across sessions via a growing library, with real production deployment evidence for the behavioral-rules approach), (3) **recursive harness/meta-agent redesign with archived variant populations** (DGM, ADAS, Self-Harness, Harness², RHI — the agent or a meta-agent edits its own scaffold/code/harness, validates via regression testing or benchmark probes, and keeps a branching archive of variants rather than one linear improvement chain). The archive/population idea (DGM, Harness²'s harnessing-level library, ADAS) looks like the most consequential advance over a simple "propose, evaluate, keep-or-discard" loop, since it explicitly defends against greedy local optima by letting weaker-looking variants seed later gains.
- Anthropic's "Dreaming" is the clearest *production* example of automatic postmortem generation (reviewing past session transcripts for recurring errors and synthesizing playbooks) at a major AI lab, but it is a commercial feature description, not a published research methodology — technical details (how patterns are mined, how playbooks are validated before reuse) were not found in these sources.
